# Verification Gate

这个技能统一“什么叫完成”。

## 核心原则

只有在拿到足够证据后，才能说完成。

证据优先级：

1. 实际运行结果
2. 测试 / lint / typecheck / build
3. 代码路径与静态分析
4. 合理推断

如果只有第 4 类证据，就不能把结论说得像已验证事实。

## 验证选择规则

按任务选择最小充分验证集：

### 文档/说明类

- 目视检查
- 链接/路径检查

### 单文件逻辑修改

- 相关测试
- 最小编译或静态检查

### 跨文件功能修改

- 相关测试
- lint / typecheck
- 至少一条端到端行为证据或调用路径证据

### 高风险任务

- 必须有明确验证步骤
- 能跑就跑
- 不能跑要说明缺口和风险

## 输出要求

收尾时区分三类信息：

- `Verified`: 已实际验证
- `Inferred`: 根据代码或上下文推断
- `Not Verified`: 还没验证、无法验证或受环境限制

## 常见反模式

- 只看代码就说“没问题”
- 跑了无关测试就说“已验证”
- 有报错但不提
- 明明没运行却写成“通过”

## 完成门

除非用户明确不要，否则任何中型以上改动都应经过一轮 `verification-gate` 思维检查。
