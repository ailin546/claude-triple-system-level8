# 系统分诊

用这个技能给任务分级，并决定后续执行路线。

## 适用场景

- 用户需求比较大，需要先判断直接做还是先计划
- 任务可能跨多个模块或多个文件
- 任务包含高风险关键词
- 不确定是否值得启用并行 agent
- 需要避免“小题大做”或“重活轻做”

## 输出格式

输出一个简洁路由结果，包含：

- `模式`：`Fast` / `Standard` / `Heavy`
- `路径`：直接回答 / 直接实现 / 先计划 / 计划后并行
- `理由`：1 到 3 条
- `检查点`：本任务最关键的完成证据

## 路由规则

### Fast：快速任务

适用于：

- 单文件小改
- 文案、脚本、配置微调
- 解释、分析、答疑
- 影响范围非常小的 bugfix

动作：

- 直接做
- 只做最相关验证
- 不强制输出计划

### Standard：标准任务

适用于：

- 普通跨文件开发
- 一般 bugfix
- 测试补齐
- 小到中型重构

动作：

- 先形成简短计划，或至少说明步骤
- 再实现
- 最后验证

### Heavy：重型任务

适用于：

- 认证、权限、支付、安全
- 数据库、接口或状态迁移
- 部署、生产问题、回滚
- 并发、性能关键路径
- 多 agent 协作明显更合适的大任务

动作：

- 明确风险、边界、验收标准
- 优先走 `$plan-execute`
- 必要时再拆并行执行

## 并行判定

只有同时满足下列条件才建议并行：

1. 子任务之间低耦合
2. 写入文件范围可分离
3. 主线程有明确的本地下一步，不会立刻被子任务结果阻塞

否则默认单线程推进。

## 禁止事项

- 不要因为任务看起来“正式”就默认走 Heavy
- 不要在事实未查清前把任务升级成系统级危机
- 不要给出大而空的 5 步模板计划

## 成功标准

分级结果应该能直接指导下一步动作，而不是只是贴标签。
