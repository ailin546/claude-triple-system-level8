# 轻量自动研究

这个技能借鉴 `codex-autoresearch` 的可验证迭代思想，但按本框架的胶水原则做轻量化：前台执行、有限轮次、低噪音、可回退、不自动 commit。

## 适用场景

- 修复一批测试失败
- 提高测试覆盖率
- 降低 lint / typecheck 错误数
- 优化一个可测性能指标
- 改善 release readiness / quality gate
- 安全、稳定性、质量类问题有明确验证命令

## 不适用场景

- 目标不可度量，只是探索想法
- 需求边界不清，应先用 `$clarify-scope`
- 需要产品或架构取舍，应先用 `$plan-execute`
- 涉及生产、凭据、不可逆数据操作
- 用户没有授权运行相关验证命令

## 核心原则

1. 先定义指标，再动手。
2. 每轮只做一个聚焦改动。
3. 改动必须通过验证命令和守护命令。
4. 指标变好且守护不退化才保留。
5. 失败时回退或改方向，不盲目堆改动。
6. 默认不后台运行，不自动 commit，不自动 push。

## 启动前简报

执行前先写清楚：

```markdown
## Autoresearch Lite Brief

- 目标：
- 范围：
- 主指标：
- 方向：提高 / 降低 / 消除 / 保持
- 基线命令：
- 验证命令：
- 守护命令：
- 迭代上限：
- 保留规则：
- 回退规则：
- 停止条件：
```

## 默认轮次

- 小任务：最多 2 轮
- 标准任务：最多 3 轮
- 重型或高风险任务：先计划，不直接进入循环

如果用户没有指定轮次，默认最多 3 轮。

## 每轮流程

1. 读取当前失败或指标输出
2. 形成一个最小改动假设
3. 实施最小改动
4. 运行验证命令
5. 运行守护命令
6. 判断保留、回退或停止
7. 记录本轮结果

## 保留 / 回退规则

### 保留

满足全部条件才保留：

- 主指标变好，或目标失败数减少
- 守护命令未退化
- 改动范围符合启动前简报
- 没有引入新的高风险问题

### 回退

出现以下情况应回退或改方向：

- 主指标不变或变差
- 守护命令失败
- 改动明显超出范围
- 需要大规模重构才能继续
- 连续两轮没有有效进展

## 结果日志

每轮结束后记录：

```markdown
### Iteration N

- 假设：
- 改动：
- 验证：
- 守护：
- 结果：保留 / 回退 / 停止
- 下一步：
```

适合记录到：

- `.memory/handoff.md`
- `.memory/today.md`
- 最终回复中的简短摘要

## 与其他 skills 的关系

- 边界不清：先 `$clarify-scope`
- 影响面较大：先 `$plan-execute`
- 完成前：用 `$verification-gate` 思维收尾
- 非平凡改动：考虑 `$code-review-gate`
- 跨会话：用 `$handoff-memory`

## 禁止事项

- 不自动 commit
- 不自动 push
- 不默认后台运行
- 不在没有基线和验证命令时开始循环
- 不把失败验证说成成功
- 不把“指标可能变好”说成“已验证变好”
